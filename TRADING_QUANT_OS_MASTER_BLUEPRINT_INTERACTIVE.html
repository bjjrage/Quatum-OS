Tesis

Mercados binarios de Polymarket pueden divergir de una referencia profesional derivada de opciones de Deribit.

No asumimos que Deribit “tenga razón”; eso se valida.

Naturaleza del trade

Con USD 2.000 no asumimos hedge perfecto en Deribit. La primera versión es relative-value / informed directional, no arbitraje risk-free.

Fair value

  • La distribución de opciones es risk-neutral, no probabilidad física verdadera.
  • Phase 1 produce una banda de referencia/fair value con incertidumbre.
  • Cualquier RN → physical calibration futura debe ser empírica y out-of-sample.
BUY YES:
FairValueLow - ExecutableAsk - Fees - Slippage - OtherCosts > 0

SELL / SHORT YES:
ExecutableBid - FairValueHigh - Fees - Slippage - OtherCosts > 0
Deribit inverse options: documentar quote convention, premium denomination y unidades. Preferir surface en IV/total variance. Si se usa Breeden–Litzenberger sobre precios, convertir explícitamente y testear contra un caso Black-76 conocido para detectar errores de signo, descuento y unidades.
Polymarket fees: guardar estructura completa y versionada, no un único bps. El backtest registra FEE_MODEL_VERSION.

4. Línea B — Behavioral Alpha

Industrializar la intuición manual: impulse → overshoot → retracement.
IMPULSE → OVERSHOOT → SHORT-HORIZON RETRACEMENT

Técnica manual original

  • Futuros; históricamente ~3× leverage, pero el leverage no crea edge.
  • Horizonte visual principal: ~5–10 minutos.
  • Se buscaba capturar solo una fracción del contra-movimiento.
  • Caída fuerte → agotamiento → rebote → long → salida.
  • Subida fuerte → overshoot → pullback → short → salida.

Intuición histórica

Ejemplo mental: si el movimiento era 15, tomar 3–5 del retroceso podía ser suficiente.

No se congela 1/3, bps ni porcentaje. Los datos determinan ratios, timeouts, MFE y MAE.

Qué NO es

  • No es HFT.
  • No compite por 20–100 ms de price discovery.
  • No depende de queue priority.
  • No es “order-book imbalance scalping” puro.
  • No intenta predecir un trend flip completo.

Hipótesis

NivelPreguntaOrden
General¿Impulsos extremos normalizados por volatilidad muestran retracement explotable?1
Clusters¿Cambia por liquidez, volatilidad, market cap y régimen?2
Activo¿Algunos tokens tienen comportamiento longitudinalmente persistente?3, solo si lo ganan

Event study

  • 100–200 contratos históricos cuando sea posible.
  • Impulso definido por log/percentage return normalizado por realized volatility previa.
  • Medir forward returns, retracement ratio, MFE, MAE y time-to-retracement.
  • Long y short se estudian por separado.
  • Comparar contra baseline del mismo activo/contexto.
  • FDR / multiple-testing correction obligatoria.
  • Cross-asset + longitudinal validation.

Forced vs Informative

Informative Move

Hack, delisting, noticia material, cambio regulatorio/fundamental. Puede no revertir.

Forced / Liquidity Move

Liquidaciones, stops, deleveraging, pánico, retiro de liquidez. Puede producir overshoot y retracement.

Tradability

edge neto + frecuencia + spread + slippage + depth + estabilidad + capacity + regime similarity
→ ACTIVE / WATCH / REDUCED / PAUSED
Batch 0 empezará además a grabar forward microstructure de una muestra inicial de 20–40 perps por tiers de liquidez, sujeto a medición de costo/CPU/storage a las 72 h.

5. Contexto, régimen y Policy Engine

Conservar la ventaja contextual humana sin permitir improvisación no testeable.
Global Context
→
Domain Regime
→
Strategy Regime
→
Asset State
→
Validated Profile

No existe un único “sentimiento del día” universal. El contexto se interpreta por dominio y estrategia.

Luna NO cambia take-profit, stop o size directamente. El flujo correcto es: contexto → estado estructurado → Policy Engine determinístico → perfil validado.

Scalping por régimen

Ejemplos conceptuales: un régimen favorable a longs puede permitir target/timeout/size mayores; uno adverso puede reducir size, exigir más confirmación o deshabilitar longs. Los números solo existen si fueron validados.

Backtest de régimen

  • Solo variables point-in-time: tendencia, realized volatility, funding, breadth, BTC state, OI, etc.
  • No usar LLMs generales para etiquetar históricos.
  • Cada régimen necesita muestra independiente suficiente; si no, fusionar o eliminar perfiles.

10. Kill Criteria

Evitar líneas infinitas de investigación.

Línea A

  • Expectancy neta no defendible.
  • Edge desaparece con executable prices y costos realistas.
  • Falla holdout o paper.
  • Capacity demasiado baja.
  • Reference/fair-value model inestable.

Línea B

  • Retracement condicional no supera baseline después de costos.
  • Edge económico menor a ~1.5–2× round-trip cost como filtro provisional.
  • No sobrevive multiple-testing correction.
  • Falla validation/holdout.
  • Parámetros inestables o extremadamente específicos.
  • No hay persistencia longitudinal/capacity.
  • Requiere fills irreales.

Timebox: 3–4 semanas como checkpoint. Si no aparece evidencia defendible, ARCHIVE.
